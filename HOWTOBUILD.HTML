tclkit > Building the tclkits

Tcl 8.4 / 8.5 / 8.6 (Metakit, sdx) | Tcl 9 (zipfs) | Build

How to build the tclkit executables for Tcl/Tk 8.4, 8.5, 8.6 and 9.0 on Windows with MSYS2 / MinGW-w64, and how to pack them into the archives found in the download area.

Prerequisites

An MSYS2 installation with the MinGW-w64 toolchain. Start the MSYS2 MINGW64 shell (not the plain MSYS one) and make sure these are there:

$ pacman -S --needed mingw-w64-x86_64-gcc make patch p7zip zip curl

The scripts have been used with gcc 16.1. Recent compilers reject much of what was ordinary C when Tcl 8.4 was written; config.sh detects gcc 14 or later and adds -std=gnu17 -fpermissive for the 8.x builds by itself.

On Linux the same scripts work with gcc, g++, make, patch, curl and the development files of X11, Xft and fontconfig (tested on AlmaLinux 8, gcc 8.5). The archives are then named tclkit-large-<version>-linux-x86_64 and are written as .tar.gz when there is no 7z.

Everything in one step

$ sh mkdist.sh

For every release listed in VERSIONS at the top of the script (8.4.20, 8.5.19, 8.6.18 and 9.0.4) this

  1. downloads the Tcl and Tk sources from SourceForge into dl/ and unpacks them to <root>/tcl and <root>/tk, where <root> is 8.4, 8.5, 8.6 or 9.0
  2. applies the patches in patches/
  3. configures and builds <root>/kit-large and <root>/kit-small
  4. packs the results into dist/tclkit-large-<version>-win-amd64.7z and dist/tclkit-small-<version>-win-amd64.7z
sh mkdist.sh 8.6.18 9.0.4
build just these releases
sh mkdist.sh -c
remove the build areas first (clean rebuild)
sh mkdist.sh -j 4
number of parallel make jobs; the default is the number of processors

 

A build that is already complete is not repeated, so the script can simply be run again after a failure or a change.

gui has Tk linked in statically and no console; dyn is a console executable which carries Tk as a shared library and loads it on package require Tk.

Building a single configuration

$ sh fetch.sh 8.6 8.6.18                       # sources -> 8.6/tcl, 8.6/tk
$ sh config.sh 8.6/kit-large cli gui mk thread allenc allmsgs tzdata
$ cd 8.6/kit-large
$ make -j8

config.sh writes 8.6/kit-large/Makefile, a few settings followed by an include of makefile.include (8.x) or makefile9.include (9.x). The build happens in build/ below that directory and leaves the executables next to the Makefile. The last step of every build runs validate.tcl / validate9.tcl with the new executable, which checks that the static packages load in the main interpreter, in a child interpreter and in a thread.

make clean removes build/, make distclean the executables as well.

Tcl 9

Tcl 9 has zipfs in the core, so its tclkit needs neither Metakit nor vlerq nor tclvfs. makefile9.include builds a static Tcl (and Tk), links the unmodified tclAppInit.c / winMain.c with kitInit9.c and lets setupvfs9.tcl attach a zip archive with the script libraries:

tcl_library/
Tcl script library, trimmed according to allenc, allmsgs, tzdata
tk_library/
Tk script library (gui, dyn)
lib/
package indexes of the static extensions, the Tk dll (dyn), starkit and tclkit::wrap

 

kitInit9.c adds what the stock shells do not do: it registers the static extensions, runs tclkit app.kit for a zip archive with a main.tcl inside, and implements tclkit -wrap. See HOWTOUSE9.HTML.

Patches

fetch.sh applies patches/tcl<root>/*.patch and patches/tk<root>/*.patch after unpacking. They are what the old releases need to compile and work with a current MinGW-w64:

tcl8.4, tk8.4: mingw-w64-seh
EXCEPTION_REGISTRATION clashes with a type of the same name in the current Windows headers; renamed as Tcl 8.5 did
tcl8.4: win64-threadid
the id of a new thread had random upper 32 bits on Win64, so thread::send could not find the thread; fix taken from Tcl 8.5
tk8.4, tk8.5: controlmask
ControlMask clashes with a struct member in the current Windows headers; made an enum as Tk 8.6 did

 

When a build fails

  • The output of make is in <root>/kit-<kind>/build.log.
  • A part that failed half-way is moved to build/<name>.failed, where its config.log can be inspected. The next run starts that part afresh.
  • If make was killed, a half-built directory can remain in build/ and is then taken for a finished one. Remove it, or use sh mkdist.sh -c.
  • To use another release, change VERSIONS in mkdist.sh or name the versions on the command line. fetch.sh replaces a source tree of a different version.
