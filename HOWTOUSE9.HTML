tclkit > Building Tcl 9 single file applications

Tcl 8.4 / 8.5 / 8.6 (Metakit, sdx) | Tcl 9 (zipfs) | Build

This is a step-by-step guide to turning a Tcl/Tk program into a single file executable with the Tcl 9 tclkit. The procedure is nearly the same as with the 8.x tclkits; the difference is the last step, which does not use sdx.

What is different from 8.x

An 8.x tclkit appends a Metakit database to the executable and mounts it through tclvfs. Tcl 9 has zipfs in the core, so the Tcl 9 tclkit appends an ordinary zip archive instead. Metakit, vlerq and tclvfs are not part of it.

A Metakit based .kit file made for 8.x, sdx.kit included, cannot be run by the Tcl 9 tclkit. Wrap the application again from its source directory (*.vfs).

The session below assumes that tclkit-cli.exe was renamed to tclkit.exe. The sample application, demo.exe, prints the sum of the numbers given on the command line, using a package called adder.

Step 1: create the directory layout

The layout is the one used with 8.x. The top-level directory may have any name; demo.vfs follows the usual convention.

D:\Temp> mkdir demo.vfs
D:\Temp> mkdir demo.vfs\lib
D:\Temp> mkdir demo.vfs\lib\adder
D:\Temp> mkdir demo.vfs\app

Step 2: copy any required packages

Packages go below the lib subdirectory.

# File: demo.vfs/lib/adder/adder.tcl
proc add args {
    return [tcl::mathop::+ {*}$args]
}
package provide adder 1.0
# File: demo.vfs/lib/adder/pkgIndex.tcl
package ifneeded adder 1.0 [list source [file join $dir adder.tcl]]

Step 3: add your application files

# File: demo.vfs/app/demo.tcl
package require adder
puts "The sum is [add {*}$::argv]"

Step 4: create the main script

The startup script must be called main.tcl and sit at the top level. What you used with 8.x works unchanged.

# File: demo.vfs/main.tcl
package require starkit
starkit::startup
source [file join $starkit::topdir app demo.tcl]

starkit::startup sets $starkit::topdir and adds the lib directory to auto_path. Its result tells how the application was started:

starpack
from the main.tcl inside the executable (demo.exe)
starkit
from a zip based kit file (tclkit demo.kit)
unwrapped
from the plain directory (tclkit demo.vfs/main.tcl)
sourced
sourced by another script

 

Step 5: build the executable

Instead of sdx, use the -wrap option built into the tclkit. There is no need to make a copy of the runtime first, nor to rename the result afterwards.

D:\Temp> tclkit -wrap demo.exe demo.vfs
demo.exe (2571145 bytes)

D:\Temp> demo 1 2 3
The sum is 6

The executable runs on any system by just copying it. It needs neither an installed Tcl nor any other supporting files.

For a GUI application, name a runtime that includes Tk with -runtime. The wrapping itself is still done by the console tclkit.

D:\Temp> tclkit -wrap demo.exe demo.vfs -runtime tclkit-gui.exe

On Windows, -icon gives the executable the icons of an .ico file. All image sizes in the file are used. With a Tk runtime the default icon of the windows changes as well.

D:\Temp> tclkit -wrap demo.exe demo.vfs -runtime tclkit-gui.exe -icon demo.ico

Building a kit file

If the name of the target ends in .kit, .zkit or .zip, the result is a zip archive with just the application and no runtime. Run it with a tclkit.

D:\Temp> tclkit -wrap demo.kit demo.vfs
demo.kit (751 bytes)

D:\Temp> tclkit demo.kit 1 2 3
The sum is 6

A kit file is a plain zip archive, so any archiver can create or unpack one. Stay with ordinary deflate compression: zip64, strong encryption and other methods such as bzip2 are not supported by Tcl.

Running without wrapping

During development there is no need to wrap at all; run main.tcl directly.

D:\Temp> tclkit demo.vfs\main.tcl 1 2 3
The sum is 6

Variables and commands worth knowing

$starkit::topdir
Top-level directory of the application: //zipfs:/app in an executable, //zipfs:/kit/name for a kit file.
$::tcl::kitpath
Path of the tclkit executable, as in 8.x.
$::tclkit::archive
Path of the kit file, when started from one.
zipfs list
Lists every file in the mounted archives.
zipfs mount file mountpoint
Mounts another zip file.
zipfs mkzip / mkimg
The low level commands of Tcl 9. zipfs mkimg does not add the Tcl library of the runtime by itself; -wrap does, so prefer -wrap.

 

Notes for those coming from 8.x

  • Files inside the executable are read-only. New files cannot be created, and a change to an existing file stays in memory and is not saved. Keep settings and other data outside the executable, for instance next to it ([file dirname [info nameofexecutable]]) or in the user's folder.
  • Paths inside an archive are case-sensitive, on Windows too.
  • Code that uses vfs::mk4, vfs::zip, Mk4tcl or vlerq directly has to be changed to the zipfs command.
  • A DLL extension inside the archive can be loaded with load; Tcl copies it to a temporary directory first. The extension has to be built for Tcl 9: a DLL made for 8.x does not load.
  • itcl is version 4.x, not 3.x (large package).
  • For the changes of Tcl 9 itself, such as the stricter handling of encodings and the removal of the automatic ~ expansion in file names, see the Tcl 9.0 release notes.
